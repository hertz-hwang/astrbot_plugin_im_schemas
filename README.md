# astrbot_plugin_im_schemas

输入法码表查询插件 for [AstrBot](https://github.com/AstrBotDevs/AstrBot)。
支持用户上传自定义码表（TSV 格式），查询任意汉字 / 词语的输入法编码，并以图片形式直观展示打法、选重、缺字、码长、当量等信息。

## 功能特性

- **多用户多码表**：每位用户可上传若干个私有码表（默认上限 3，管理员不限）。
- **词频查询**：另可上传「字词\t词频」表，用 `[词频名] <字词1> [<字词2> ...]` 查询字词频率。
- **智能切分**：对长文本自动用 DP 求最少按键数的切分方案，自动识别词组与单字。
- **强制单字查询**：用引导键（默认 `!`）前缀可强制按字逐一查询，跳过词组组合。
- **all 组聚合对比**：一次查询多个方案的结果，自动按码长 / 选重 / 当量 / 缺字排序。
  - ≤10 字符：每个方案输出完整打法图，竖向拼接。
  - >10 字符：表格化展示各方案的统计指标。
- **图片渲染**：
  - 单字模式：大字 + 所有同码字词的位序。
  - 多字模式：每段字 / 词组下方标注码串，颜色区分（黑=单字、绿=词组、红=选重、紫=缺字、蓝=自编码）。
  - 缺字以紫色 `??????` 醒目标记。
- **统计信息**：码长（按字均摊）、选重数、缺字数、按键对当量、文本难度（基于 Unicode 区段）。
- **多字体回退**：内置 ChaiPUA、思源黑体、Plangothic 三款字体，按 cmap 自动选择，PUA 区扩展字也能正常显示。
- **私聊上传引导**：私聊发送 `.txt` 文件时，自动提示完整的上传命令格式。

## 安装

```bash
# 在 AstrBot 插件目录下
git clone https://github.com/hertz-hwang/astrbot_plugin_im_schemas
```

依赖会通过 `requirements.txt` 自动安装：

```
Pillow>=10.0.0
aiohttp>=3.8.0
fonttools>=4.0.0
```

## 使用方法

### 1. 上传码表

私聊发送 `.txt` 格式的 TSV 码表文件，然后**引用回复**该文件消息发送：

```
khkh上传词提 [词提名]
```

示例：

```
khkh上传词提 五笔86
```

如需调整选重键 / 最大长度 / 标点引导键，使用「设置词提」单独配置（见下文）。重复上传同名词提只会刷新码表条目，不会重置已设置的参数。

**码表文件格式**（TSV，Tab 分隔）：

```
a	工
ggll	功劳
b	了
# 以 # 开头的行为注释
```

### 2. 设置词提参数

```
khkh设置词提 [词提名] 选重键=_;'4567890
khkh设置词提 [词提名] 最大长度=4
khkh设置词提 [词提名] 标点引导键=/
```

每条指令仅修改一项，未修改的项保持原值。设置一次后会持久保存，再次重新上传同名码表也不会被重置。

参数说明：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `选重键` | `_;'4567890` | 第 1 位用首键省略 / 空格首选，第 2 位起依次取此串字符 |
| `最大长度` | `4` | 编码最长位数；不足时第 1 位补首选键 |
| `标点引导键` | （无）| 预留字段 |

### 3. 查询编码

```
[词提名] <字词>
```

示例：

```
五笔86 中国人民
```

引用回复一段文本并发送 `[词提名]` 也可以查询整段文本（赛文格式会自动剥离首末段）。

### 4. 强制单字查询

在词提名前加引导键 `!`（默认）：

```
!五笔86 中国人
```

跳过词组组合，每个字独立查码。

### 5. 编码反查

```
/[词提名] <code1> [<code2> ...]
```

示例：

```
/五笔86 ggll a
```

返回每个 code 在该方案下对应的字词，按码表录入顺序给出位序（位序 ≥2 的选重以红色标记）。也支持 all 组：

```
/all ggll
```

### 6. all 组对比

需先在插件配置中将方案名加入 `all_schemas` 列表，再用配置的触发词查询：

```
all 中国
```

### 7. 词提信息

```
%[词提名]
```

显示该方案的选重键、最大长度、所用码元等。

### 8. 列出 / 删除

```
khkh所有词提                  # 列出全部已上传词提
khkh删除词提 [词提名]         # 仅上传者可删
```

## 词频查询

除码表外，还支持上传**词频表**，查询任意字词的频率。词频功能与词提相互独立，只有「上传 → 查询」一条路径，不涉及切分、选重、当量等逻辑。

### 上传词频

私聊发送 `.txt` 文件，然后**引用回复**该文件消息：

```
khkh上传词频 [词频名]
```

示例：

```
khkh上传词频 常用词频
```

**词频文件格式**（TSV，Tab 分隔，注意列序与码表相反）：

```
的	1234567
中国	45678
# 以 # 开头的行为注释
```

第一列为字词，第二列为词频（原样保存与显示，整数 / 小数均可）。同一字词重复出现时保留首次的值。

> 词频名与词提名**共用同一套命名空间**：已被词提占用的名称不能用作词频名，反之亦然。

### 查询词频

```
[词频名] <字词1> [<字词2> ...]
```

示例：

```
常用词频 的 中国 量子
```

返回纯文本：

```
【常用词频】
的 → 1234567
中国 → 45678
量子 → 未收录
```

一次最多查询 100 个字词，超出部分会被省略。

### 词频管理

```
%[词频名]                        # 查看来源与条目数
khkh所有词频                     # 列出全部已上传词频
khkh设置词频 [词频名] 来源=别名   # 仅上传者可改
khkh删除词频 [词频名]            # 仅上传者可删
```

## 配置项

在 AstrBot 插件管理界面修改 `_conf_schema.json` 对应字段：

| 字段 | 说明 | 默认 |
|------|------|------|
| `all_schemas` | all 组方案名列表（每行一个） | `[]` |
| `all_trigger` | all 组触发词（支持正则，留空禁用） | `all` |
| `single_char_prefix` | 强制单字查询引导键（支持正则，留空禁用） | `!` |
| `member_max_schemas` | 非管理员可上传词提上限（≤0 表示不限） | `3` |
| `member_max_freqs` | 非管理员可上传词频上限（≤0 表示不限） | `3` |
| `plugin_admins` | 插件管理员 user_id 列表（与系统管理员享有同等权限） | `[]` |

### 关于权限

本插件中“管理员”的判定规则如下，满足**任一条件**即视为管理员：

1. AstrBot 系统级管理员（`event.is_admin()` 为真）；
2. 发送者 `user_id` 出现在插件配置的 `plugin_admins` 列表中。

通过 `plugin_admins` 字段，系统管理员可以在 AstrBot 插件管理页中维护一份与本插件相关的独立名单，无需将用户提升为 AstrBot 全局管理员。插件管理员享有：

- 跳过 `member_max_schemas` / `member_max_freqs` 上传数量上限；
- 跳过 `MAX_UPLOAD_MB` 单文件大小限制；
- 可使用任意长度的词提 / 词频名（含单字符）；
- 可修改 / 删除他人上传的词提与词频（包括设置 `PUA` 自定义字体）。

修改 `plugin_admins` 后无需重启插件，下次请求即生效。

## 项目结构

```
astrbot_plugin_im_schemas/
├── main.py                # 插件主体
├── metadata.yaml          # AstrBot 元数据
├── _conf_schema.json      # 配置项 schema
├── pair_equivalence.txt   # 按键对当量表（用于当量计算）
├── requirements.txt
└── fonts/
    ├── ChaiPUA-0.2.7.ttf
    ├── SourceHanSansSC-Regular.otf
    └── Plangothic.ttc
```

数据存储位于 AstrBot 数据目录下的 `im_data/schemas.db`（SQLite，WAL 模式）。其中 `schemas` / `codes` 表存码表，`freqs` / `freq_entries` 表存词频。

## 实现要点

- **DP 切分**：`_query_segments` 用动态规划找最少按键数的切分；候选子串长度由码表中最长词限定。
- **首选键省略**：当一段普通编码后接自编码标点、`pos==1` 且 `len(code)<max_len` 时，省略首选键。
- **缺字处理**：未命中码表的字符不计入码长，但参与缺字数统计。
- **基线统一**：多字体回退时使用最大 ascent 作为统一基线，避免 PUA 字符高度错位。
- **缓存**：字体 cmap、字符 bbox、字体对象均按需缓存，长文本渲染基本只查一次。
